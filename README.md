# OctoAcme Project Management Docs

## Overview

The OctoAcme process is designed for open, iterative, and accountable project delivery. It follows a structured, lifecycle-based approach grounded in five core principles:

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

The OctoAcme project management framework spans five key phases:
1. **Initiation**: Problem statement, stakeholders, high-level timeline
2. **Planning**: Scope, resources, milestones, dependencies
3. **Execution**: Build, test, review, iterate
4. **Release**: Deploy, verify, announce
5. **Retrospective**: Capture learnings and next steps

## Core Roles

- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications
- **Developers**: Implement features, collaborate on design and testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs and approvals

## Quick Start for New Team Members

1. **Start here**: Read [Project Management Overview](octoacme-project-management-overview.md) for context and high-level process flow
2. **Know your role**: Review [Roles & Personas](octoacme-roles-and-personas.md) to understand your responsibilities
3. **Learn by phase**: Reference the phase-specific guides (Initiation, Planning, Execution, Release, Retrospective) as you work through projects
4. **Stay informed**: Use the Risk Management & Communication guide for stakeholder updates and escalation paths

## Key Communication Cadence

- **Daily**: 15-minute standups (progress, blockers, dependencies)
- **Weekly**: PM + PdM alignment sync; team delivery syncs; risk register review
- **Sprint/Milestone end**: Demo/Review and retrospective
- **Monthly**: Stakeholder updates

## How to Use This Documentation

- Keep the Project Charter updated in your project repository
- Add process-specific docs to `.copilot/` if you want Copilot Spaces to use them as context
